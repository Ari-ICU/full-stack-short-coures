## ✊ ការបញ្ជាក់ប្រភេទ (Type Assertions)

ពេលខ្លះ ក្នុងនាមជាអ្នកសរសេរកម្មវិធី អ្នកមានព័ត៌មានច្បាស់លាស់អំពីប្រភេទទិន្នន័យណាមួយ **ច្រើនជាងអ្វីដែល TypeScript អាចដឹង** ទៅទៀត! 

ឧទាហរណ៍ ពេលអ្នកចាប់យក HTML Element ចេញពីគេហទំព័រ៖
```ts
// TypeScript គ្រាន់តែដឹងថាវាជា HTMLElement ធម្មតាមួយ តែមិនដឹងថាវាជាអ្វីពិតប្រាកដទេ!
const myCanvas = document.getElementById("main_canvas");
```
បើអ្នកព្យាយាមគូសវាសនៅលើវា TypeScript នឹងលោត Error ព្រោះវាខ្លាចអ្នកចាប់បានអក្សរ `<p>` ឫអីផ្សេង។ 
នៅទីនេះហើយដែលអ្នកត្រូវប្រើពាក្យ **`as`** ដើម្បីបញ្ជាក់ប្រាប់វាថា "ជឿខ្ញុំទៅ! ខ្ញុំច្បាស់ណាស់ថាវាជា Canvas!"៖

```ts
// យើងប្រាប់ TS ថា 'ឯងមិនបាច់បារម្ភទេ ខ្ញុំដឹងថាវាពិតជា HTMLCanvasElement មែន!'
const myCanvas = document.getElementById("main_canvas") as HTMLCanvasElement;

// ឥឡូវនេះ TS អនុញ្ញាតអោយអ្នកហៅមុខងាររបស់ Canvas ទាំងស្រុង
const ctx = myCanvas.getContext("2d"); 
```

> ⚠️ **បម្រាម:** កុំប្រើ `as` ផ្តេសផ្តាសដើម្បីតែបំបិទភ្នែក TypeScript អោយសោះ! បើអ្នកកុហកវា (ឧ. អថេរនោះជាអក្សរសោះ តែអ្នកទៅ `as number`) នោះកូដរបស់អ្នកនឹងគាំងពេលរត់ជាក់ជាមិនខាន។

## 🔒 Const Assertions (`as const`)

នេះគឺជាមុខងារមួយដែលពេញនិយមបំផុត! `as const` ត្រូវបានគេប្រើដើម្បី **បង្កក (Freeze)** ទិន្នន័យ (Object ឫ Array) អោយនៅថេរជារៀងរហូត។

ស្រមៃថាអ្នកមាន Object ផ្ទុកព៌ណរបស់ក្រុមហ៊ុន៖

```ts
// របៀបធម្មតា
const colors = {
  primary: "#FF0000",
  secondary: "#00FF00"
};
// ទោះបីជាប្រកាស const តែយើងនៅតែអាចកែវាបាន!
colors.primary = "BLUE"; // គ្មានបញ្ហាទេ (តែវាមិនល្អទេព្រោះជាទិន្នន័យក្រុមហ៊ុន)
```

**ដំណោះស្រាយជាមួយ `as const`:**

```ts
// របៀបទំនើប និងមានសុវត្ថិភាពខ្ពស់
const companyColors = {
  primary: "#FF0000",
  secondary: "#00FF00"
} as const; // បញ្ជាក់ថា នេះគឺជាទិន្នន័យអចិន្ត្រៃយ៍!

// ❌ Error! TypeScript នឹងស្រែកប្រាប់ភ្លាមថា Properties ទាំងនេះគឺ readonly!
// companyColors.primary = "BLUE"; 
```

អ្វីដែលអស្ចារ្យជាងនេះទៅទៀតនោះគឺ TypeScript លែងចាត់ទុកតម្លៃនោះជា `string` ទៀតហើយ តែវាចាត់ទុកវាជាប្រភេទ **`"#FF0000"`** (Literal Type) តែម្តង ដែលធ្វើអោយមានសុវត្ថិភាពទ្វេដង!
