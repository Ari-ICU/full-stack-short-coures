## 🔒 អ្វីទៅជា Readonly?

ពេលខ្លះ យើងមានទិន្នន័យមួយចំនួននៅក្នុង Object ដែលយើងចង់អោយវានៅថេរជារៀងរហូត បន្ទាប់ពីវាត្រូវបានបង្កើតរួច។ 
ឧទាហរណ៍ នៅក្នុងប្រព័ន្ធគ្រប់គ្រងគណនី អ្នកប្រើប្រាស់អាចផ្លាស់ប្តូរ "ឈ្មោះ" ឫ "អាយុ" របស់គាត់បាន ប៉ុន្តែគាត់ **ដាច់ខាតមិនអាចផ្លាស់ប្តូរ "លេខសម្គាល់" (ID) របស់គាត់បានទេ!**

នៅក្នុង TypeScript យើងអាចការពាររឿងនេះបានយ៉ាងងាយស្រួល ដោយគ្រាន់តែបន្ថែមពាក្យ **`readonly`** នៅពីមុខឈ្មោះ Property!

---

## 1. `readonly` សម្រាប់ Objects

```ts
type User = {
  readonly id: number; // លេខសម្គាល់នេះ មិនអាចប្តូរបានទេ!
  name: string;        // ឈ្មោះ អាចប្តូរបាន
};

let myUser: User = {
  id: 12345,
  name: "Ratha",
};

// ✅ យើងអាចប្តូរឈ្មោះបានធម្មតា
myUser.name = "Sok"; 

// ❌ Error! TypeScript នឹងចាប់កំហុសភ្លាម ព្រោះ id គឺសម្រាប់តែ 'អាន' ប៉ុណ្ណោះ
// myUser.id = 99999; 
```

នេះគឺជាការការពារដ៏រឹងមាំមួយ ព្រោះទោះបីជាសមាជិកក្រុមផ្សេងទៀតរបស់អ្នកមិនដឹងពីច្បាប់នេះ ក៏គាត់មិនអាចសរសេរកូដកែប្រែ ID នេះបានដែរ!

---

## 2. `readonly` សម្រាប់ Arrays (បញ្ជី)

ការការពារ Array គឺរឹតតែមានសារៈសំខាន់ ព្រោះ Array នៅក្នុង JavaScript ងាយនឹងត្រូវបានផ្លាស់ប្តូរណាស់ (ដូចជាការប្រើ `.push()`, `.pop()`, `.splice()`) ទោះបីជាអ្នកប្រកាសវាជា `const` ក៏ដោយ!

ដើម្បីការពារបញ្ជីទាំងមូលកុំអោយមាននរណាម្នាក់អាចបន្ថែម លុប ឬកែប្រែទិន្នន័យក្នុងនោះបាន យើងអាចប្រើ `ReadonlyArray` (ឫទម្រង់ខ្លី `readonly type[]`)។

```ts
// បញ្ជីនេះត្រូវបានចាក់សោរទាំងស្រុង!
let luckyNumbers: readonly number[] = [7, 9, 11];

// ❌ Error! មិនអាចបន្ថែមលេខថ្មីបានទេ
// luckyNumbers.push(15); 

// ❌ Error! មិនអាចកែប្រែលេខនៅតំណែងទី 0 បានទេ
// luckyNumbers[0] = 8; 

// ✅ ត្រូវ! យើងអាចគ្រាន់តែអានវាប៉ុណ្ណោះ
console.log(luckyNumbers[0]); 
```

> **កំណត់សម្គាល់:** ការប្រើ `readonly` មិនមែនមានន័យថាទិន្នន័យនោះសុវត្ថិភាព 100% ពី Hacker នោះទេ! វាគ្រាន់តែជាច្បាប់វិន័យ (Rules) នៅពេលកំពុងសរសេរកូដ (Compile time) ដើម្បីអោយ Developer គ្នាឯងកុំអោយច្រឡំកែកូដខុសប៉ុណ្ណោះ។ នៅពេលវាក្លាយជា JS វាលែងមានអំណាចអ្វីទៀតហើយ។
