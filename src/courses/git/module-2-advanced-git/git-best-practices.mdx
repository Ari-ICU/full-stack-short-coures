## 🌟 ការសរសេរកូដប្រកបដោយវិជ្ជាជីវៈ

ដើម្បីក្លាយជាអ្នកសរសេរកូដដ៏ពូកែម្នាក់ ការចេះប្រើប្រាស់ឧបករណ៍តែមួយមុខគឺមិនគ្រប់គ្រាន់ទេ អ្នកត្រូវតែចេះប្រើវាអោយបានត្រឹមត្រូវតាមស្តង់ដារដែលក្រុមហ៊ុនធំៗប្រើប្រាស់។

## 📝 Commit Message Standards

Commit Message ប្រៀបដូចជាកំណត់ហេតុប្រវត្តិសាស្ត្រនៃកូដរបស់អ្នក។ ការសរសេរ Message ថា `"fix bug"` ឬ `"update"` គឺមិនល្អទេ ព្រោះវាមិនបានប្រាប់ថាអ្នកបានធ្វើអ្វីខ្លះនោះទេ។

**ទម្រង់ដែលគេនិយមប្រើ (Conventional Commits):**
- `feat:` សម្រាប់ការបន្ថែមមុខងារថ្មី (ឧ. `feat: បន្ថែមមុខងារ Login តាមរយៈ Google`)
- `fix:` សម្រាប់ការជួសជុលកំហុស (ឧ. `fix: ដោះស្រាយបញ្ហាចុចប៊ូតុងមិនដំណើរការលើទូរស័ព្ទ`)
- `docs:` សម្រាប់ការកែប្រែឯកសារ (ឧ. `docs: កែសម្រួល README.md`)
- `style:` សម្រាប់ការកែប្រែទម្រង់កូដ (ឧ. `style: តម្រឹមបន្ទាត់កូដនៅក្នុង Header`)
- `refactor:` សម្រាប់ការរៀបចំកូដឡើងវិញដោយមិនផ្លាស់ប្តូរមុខងារ
- `chore:` សម្រាប់ការកែប្រែដែលមិនពាក់ព័ន្ធនឹងកូដផ្ទាល់ (ឧ. `chore: update dependencies`)

ការអនុវត្តបែបនេះ ធ្វើអោយមិត្តរួមការងារ (និងខ្លួនអ្នកនៅថ្ងៃក្រោយ) ងាយស្រួលអានប្រវត្តិ Commit និងយល់ពីអ្វីដែលបានផ្លាស់ប្តូរ។

## 🚫 `.gitignore`

មាន File និង Folder មួយចំនួនដែលអ្នក **មិនគួរ** រក្សាទុកនៅក្នុង Git នោះទេ ដូចជា៖
1. **ឯកសារធំៗ ឬឯកសារដែលបង្កើតដោយស្វ័យប្រវត្តិ** (ឧ. `node_modules`, `dist`, `build`)
2. **ឯកសារសម្ងាត់** (ឧ. `.env` ដែលផ្ទុក Password ឬ API Keys)
3. **ឯកសាររបស់ប្រព័ន្ធប្រតិបត្តិការ** (ឧ. `.DS_Store` លើ Mac, `Thumbs.db` លើ Windows)

ដើម្បីប្រាប់ Git អោយមិនអើពើនឹងឯកសារទាំងនេះ អ្នកត្រូវបង្កើត File មួយឈ្មោះថា `.gitignore` នៅផ្នែកខាងក្រៅបង្អស់នៃ Project (Root directory) ហើយសរសេរឈ្មោះឯកសារទាំងនោះចូល៖

```text
# ឧទាហរណ៍នៃ .gitignore
node_modules/
.env
.DS_Store
dist/
*.log
```

## 🌊 Git Flow

**Git Flow** គឺជាគំរូនៃរចនាសម្ព័ន្ធ Branch ដែលរៀបចំឡើងយ៉ាងមានសណ្តាប់ធ្នាប់សម្រាប់ការអភិវឌ្ឍន៍ Software ខ្នាតធំ។ 

ជាទូទៅ វាមាន Branch សំខាន់ៗដូចជា៖
- **`main`**: ផ្ទុកកូដដែលកំពុងដំណើរការផ្ទាល់ (Production) សម្រាប់អ្នកប្រើប្រាស់។ មិនមាននរណាម្នាក់ត្រូវបានអនុញ្ញាតអោយ Push កូដចូលផ្ទាល់ទេ។
- **`develop`**: ផ្ទុកកូដថ្មីៗដែលកំពុងសាកល្បង មុននឹងបញ្ជូនទៅ `main`។
- **`feature/*`**: (ឧ. `feature/login`, `feature/cart`) សម្រាប់សរសេរមុខងារថ្មីៗដោយផ្តាច់ចេញពី Branch ផ្សេង។ បន្ទាប់ពីសរសេរចប់ ត្រូវ Merge ចូល `develop`។
- **`hotfix/*`**: សម្រាប់ជួសជុលកំហុសបន្ទាន់ដែលកើតឡើងនៅលើ `main`។

ការប្រើប្រាស់ Git Flow ជួយកាត់បន្ថយបញ្ហាកូដរញ៉េរញ៉ៃ និងធ្វើអោយការងារជាក្រុមមានភាពរលូនបំផុត។
