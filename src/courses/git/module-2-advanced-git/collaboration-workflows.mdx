## 🤝 ការសហការគ្នាក្នុងគម្រោងតែមួយ

នៅពេលដែលអ្នកធ្វើការក្នុងក្រុមហ៊ុន ឬសរសេរកូដជាមួយមិត្តភ័ក្តិ ការចេះប្រើប្រាស់ GitHub ដើម្បីសហការគ្នាគឺជារឿងចាំបាច់បំផុត។ 

---

## 🔀 Pull Requests (PR) និង Code Review

ជាទូទៅ នៅក្នុងក្រុមហ៊ុន យើងមិនអនុញ្ញាតអោយនរណាម្នាក់ `git push` កូដចូលទៅកាន់ `main` Branch ដោយផ្ទាល់នោះទេ។ ផ្ទុយទៅវិញ យើងប្រើប្រាស់យន្តការ **Pull Request**។

**ដំណើរការទូទៅ៖**
1. អ្នកបង្កើត Branch ថ្មីមួយពី `main` (ឧ. `feature/login`)
2. អ្នកសរសេរកូដ រួច `git push origin feature/login` ទៅកាន់ GitHub
3. អ្នកចូលទៅកាន់ GitHub ហើយចុចប៊ូតុង **"Compare & pull request"**
4. សមាជិកក្រុមផ្សេងទៀត នឹងចូលមកពិនិត្យមើលកូដរបស់អ្នក (Code Review) ដើម្បីស្វែងរកកំហុស មុននឹងអនុម័ត (Approve)។
5. ក្រោយពីមានការយល់ព្រម ទើបកូដនោះត្រូវបាន **Merge** បញ្ចូលទៅក្នុង `main` Branch ជាផ្លូវការ។

យន្តការនេះធានាថាកូដដែលចូលទៅក្នុង `main` គឺមានគុណភាពខ្ពស់ និងគ្មានកំហុស។

## ⚔️ ការដោះស្រាយ Merge Conflicts

ពេលខ្លះ មនុស្សពីរនាក់អាចនឹងកែប្រែកូដនៅលើ **បន្ទាត់តែមួយ** នៃ File តែមួយ។ នៅពេលដែលព្យាយាមបញ្ចូលគ្នា (Merge) Git នឹងមិនដឹងថាត្រូវយករបស់នរណានោះទេ ពេលនោះហើយដែល **Merge Conflict** កើតឡើង។

នៅពេលមាន Conflict នោះ Git នឹងដាក់សញ្ញាសម្គាល់នៅក្នុង File នោះ ដូចនេះ៖

```text
<<<<<<< HEAD
<h1>សួស្តី ពី Branch របស់អ្នក</h1>
=======
<h1>សួស្តី ពី Branch របស់មិត្តភ័ក្តិអ្នក</h1>
>>>>>>> branch-របស់មិត្តភ័ក្តិ
```

**របៀបដោះស្រាយ៖**
1. បើក File ដែលមានបញ្ហានោះនៅក្នុង VS Code
2. អ្នកនឹងឃើញជម្រើសដូចជា "Accept Current Change", "Accept Incoming Change" ឬ "Accept Both Changes"។
3. លុបសញ្ញាសម្គាល់ (`<<<<`, `====`, `>>>>`) ចោល ហើយកែសម្រួលកូដអោយបានត្រឹមត្រូវតាមអ្វីដែលអ្នកចង់បាន។
4. បន្ទាប់ពីកែរួច សូម Save រួចធ្វើការ `git add` និង `git commit` ជាការស្រេច។

## 🍴 Forking Workflow (Open Source)

ប្រសិនបើអ្នកចង់ចូលរួមចំណែក (Contribute) ទៅកាន់គម្រោងរបស់ក្រុមហ៊ុនផ្សេង (ឧទាហរណ៍ React ឬ Tailwind CSS) ដែលអ្នកមិនមានសិទ្ធិ `push` ទៅកាន់ Repository នោះទេ អ្នកត្រូវប្រើប្រាស់ការ **Fork**។

1. ចុចប៊ូតុង **"Fork"** នៅលើ GitHub របស់គម្រោងដើម (វានឹងចម្លងគម្រោងនោះមកកាន់គណនី GitHub របស់អ្នក)
2. `git clone` គម្រោងពីគណនីរបស់អ្នកមកកាន់កុំព្យូទ័រ
3. បង្កើត Branch ថ្មី សរសេរកូដ និង `git push` ទៅកាន់គណនីរបស់អ្នក
4. ត្រលប់ទៅកាន់គម្រោងដើមវិញ ហើយបង្កើត **Pull Request** ពី Repository របស់អ្នកទៅកាន់គម្រោងដើមនោះ។

នេះជាវិធីស្តង់ដារដែលពិភពលោកប្រើប្រាស់សម្រាប់ការអភិវឌ្ឍន៍ Open Source Software!
