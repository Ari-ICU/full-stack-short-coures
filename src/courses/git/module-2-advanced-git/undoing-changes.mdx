## 🛠️ ការជួសជុលកំហុសក្នុងការសរសេរកូដ

ក្នុងនាមជាអ្នកសរសេរកូដ ការបង្កើតកំហុសគឺជារឿងធម្មតា។ ពេលខ្លះអ្នកអាចនឹងលុប File សំខាន់មួយចោល ឬសរសេរកូដខុសដែលធ្វើអោយកម្មវិធីលែងដើរ។ Git ផ្តល់នូវយន្តការដ៏មានឥទ្ធិពលដើម្បីអោយអ្នកអាច "ត្រលប់ក្រោយ" (Undo) បានយ៉ាងងាយស្រួល។

---

## 🔙 លុបចោលការផ្លាស់ប្តូរក្នុង Working Directory (`git restore`)

ប្រសិនបើអ្នកបានកែប្រែ File មួយ ប៉ុន្តែ**មិនទាន់**បាន `git add` ឬ `git commit` ហើយអ្នកចង់លុបចោលការកែប្រែនោះចោលវិញ (ត្រលប់ទៅដូចដើមវិញ):

```bash
# លុបចោលការផ្លាស់ប្តូរនៅក្នុង File ជាក់លាក់មួយ
git restore index.html

# លុបចោលការផ្លាស់ប្តូរទាំងអស់នៅក្នុង Working Directory
git restore .
```
*(ចំណាំ៖ ការប្រើប្រាស់ `git restore .` នឹងលុបការផ្លាស់ប្តូរដែលមិនទាន់បានរក្សាទុកទាំងអស់ចោល ដូច្នេះសូមប្រយ័ត្ន។)*

## ⏪ ត្រលប់ទៅកាន់ស្ថានភាពចាស់ (`git reset`)

ប្រសិនបើអ្នកបានធ្វើការ `git commit` រួចហើយ ប៉ុន្តែចង់ត្រលប់ទៅកាន់ចំណុចមុនវិញ Git មាន `git reset` ដែលមាន ៣ កម្រិត (Modes)៖

**១. `--soft`**: ត្រលប់ Commit ក្រោយវិញ ប៉ុន្តែរក្សាទុកកូដរបស់អ្នកអោយនៅដដែល ហើយដាក់វានៅក្នុង Staging Area (`git add` រួចជាស្រេច)។
```bash
git reset --soft HEAD~1
```

**២. `--mixed` (Default)**: ត្រលប់ Commit ក្រោយវិញ រក្សាកូដនៅដដែល ប៉ុន្តែដកវាចេញពី Staging Area (ត្រូវធ្វើ `git add` ឡើងវិញ)។
```bash
git reset HEAD~1
```

**៣. `--hard`**: ត្រលប់ក្រោយវិញ ហើយ**លុបចោល**កូដដែលអ្នកបានសរសេរទាំងស្រុង (Dangerous!)។
```bash
git reset --hard HEAD~1
```

*(`HEAD~1` មានន័យថាត្រលប់ក្រោយចំនួន ១ Commit)*

## 🔄 ការកែប្រែដោយសុវត្ថិភាព (`git revert`)

ប្រសិនបើអ្នកបាន `git push` កូដរបស់អ្នកទៅកាន់ GitHub ហើយ នោះការប្រើ `git reset` គឺ**មិនត្រូវបានណែនាំទេ** ព្រោះវានឹងផ្លាស់ប្តូរប្រវត្តិដែលអ្នកដទៃកំពុងប្រើ។ 

ក្នុងករណីនេះ អ្នកគួរប្រើ `git revert` ជំនួសវិញ។

```bash
# ស្វែងរក Commit ID ដែលអ្នកចង់លុបចោលការផ្លាស់ប្តូរ
git log --oneline

# ធ្វើការ Revert (ឧទាហរណ៍ Commit ID: abc1234)
git revert abc1234
```
`git revert` មិនលុប Commit ចាស់ចោលទេ ប៉ុន្តែវាបង្កើត **Commit ថ្មីមួយទៀត** ដែលមានការផ្លាស់ប្តូរ "ផ្ទុយ" ពី Commit ចាស់ (បូកក្លាយជាដក ដកក្លាយជាបូក) ដើម្បីរក្សា History អោយមានសុវត្ថិភាព។

## ✍️ កែប្រែ Commit ចុងក្រោយ (`git commit --amend`)

តើអ្នកធ្លាប់ `git commit` រួចហើយ ទើបនឹកឃើញថាភ្លេចដាក់ File មួយ ឬក៏សរសេរ Message ខុសអក្ខរាវិរុទ្ធដែរឬទេ? អ្នកមិនចាំបាច់បង្កើត Commit ថ្មីទេ អ្នកអាចប្រើ `--amend`:

```bash
# កែប្រែ Message របស់ Commit ចុងក្រោយ
git commit --amend -m "Message ថ្មីដែលត្រឹមត្រូវ"

# ឬបន្ថែម File ដែលភ្លេចចូលទៅក្នុង Commit ចុងក្រោយ
git add forgot-this-file.txt
git commit --amend --no-edit
```
*(`--no-edit` មានន័យថារក្សាទុក Message ដដែលដោយគ្រាន់តែបញ្ចូល File បន្ថែម)*
