## 🔒 អ្វីទៅជា Constraints?

**Constraints** គឺជាលក្ខខណ្ឌ ឬច្បាប់ដែលយើងដាក់កំណត់ទៅលើ Column ដើម្បីធានាថាទិន្នន័យដែលបញ្ចូលទៅក្នុង Database មានភាពត្រឹមត្រូវ មិនជាន់គ្នា និងមិនបាត់បង់ (Data Integrity)។

Constraints សំខាន់ៗមានដូចជា៖
1. **PRIMARY KEY:** កំណត់ថា Column នេះជាលេខសម្គាល់តែមួយគត់ (មិនអោយមានទិន្នន័យស្ទួន និងមិនអាចទទេរ `NULL` បានទេ)។
2. **FOREIGN KEY:** ជាចំណងភ្ជាប់ទំនាក់ទំនងរវាងតារាងមួយ ទៅតារាងមួយទៀត។
3. **UNIQUE:** កំណត់ថាទិន្នន័យក្នុង Column នេះមិនអាចជាន់គ្នាបានទេ (ឧទាហរណ៍៖ លេខទូរស័ព្ទ, Email)។
4. **NOT NULL:** កំណត់ថា Column នេះចាំបាច់ត្រូវតែមានទិន្នន័យ។
5. **CHECK:** កំណត់លក្ខខណ្ឌជាក់លាក់ (ឧទាហរណ៍៖ `CHECK (age >= 18)`)។
6. **DEFAULT:** កំណត់តម្លៃលំនាំដើម ប្រសិនបើគេមិនបានបញ្ចូលទិន្នន័យ (ឧទាហរណ៍៖ `status VARCHAR(20) DEFAULT 'pending'`)។

### Composite Primary Keys
ជួនកាល តារាងមួយ (ឧ. តារាងកណ្តាល `order_items`) មិនចាំបាច់មាន `id` ផ្ទាល់ខ្លួនទេ យើងអាចរួមបញ្ចូល Foreign Keys ទាំងពីរចូលគ្នាធ្វើជា Primary Key តែមួយបាន ដែលហៅថា Composite Primary Key។

```sql
CREATE TABLE order_items (
    order_id BIGINT REFERENCES orders(id),
    product_id BIGINT REFERENCES products(id),
    quantity INT NOT NULL,
    PRIMARY KEY (order_id, product_id)
);
```

**Foreign Key (កូនសោរបរទេស)** ត្រូវបានប្រើប្រាស់ដើម្បីចង្អុលទៅកាន់ **Primary Key** របស់តារាងមួយទៀត។

ឧទាហរណ៍៖
```sql
CREATE TABLE orders (
    id BIGINT GENERATED ALWAYS AS IDENTITY PRIMARY KEY,
    user_id BIGINT NOT NULL,
    total_price NUMERIC(10, 2) NOT NULL,
    status VARCHAR(20) DEFAULT 'pending',
    
    -- កំណត់ Foreign Key
    CONSTRAINT fk_user
      FOREIGN KEY(user_id) 
      REFERENCES users(id)
      ON DELETE CASCADE
      ON UPDATE CASCADE
);
```

### ឥទ្ធិពលនៃ ON DELETE និង ON UPDATE

នៅពេលដែលយើងលុប (DELETE) ឬកែប្រែលុខសម្គាល់ (UPDATE) User ម្នាក់ចេញពី Database តើគួរមានរឿងអ្វីកើតឡើងចំពោះ Orders របស់គាត់? 

- **`RESTRICT` (លំនាំដើម):** ការពារមិនអោយលុប/កែប្រែ User នោះទេ ប្រសិនបើគាត់មាន Orders នៅក្នុងប្រព័ន្ធ (ការពារបាត់បង់ទិន្នន័យដោយអចេតនា)។
- **`CASCADE`:** ប្រសិនបើលុប User នោះ **PostgreSQL** នឹងលុបរាល់ Orders ទាំងអស់របស់គាត់ចោលដោយស្វ័យប្រវត្តិ។
- **`SET NULL`:** វានឹងមិនលុប Orders ចោលទេ តែវានឹងប្តូរ `user_id` ទៅជា `NULL` វិញ (រក្សាប្រវត្តិបញ្ជាទិញ ទោះបីអតិថិជនលុបគណនីក៏ដោយ)។
- **`SET DEFAULT`:** ប្តូរតម្លៃទៅជាលំនាំដើមវិញ។

> ⚠️ **ច្បាប់មាស:** កុំប្រើ `CASCADE` ដោយស្វ័យប្រវត្តិអោយសោះ! ត្រូវជ្រើសរើសដោយផ្អែកលើច្បាប់អាជីវកម្ម (Business Rule)។ ឧទាហរណ៍ ការលុប User មិនគួរលុបវិក្កយបត្រ (Invoice) របស់គាត់ចោលទេ (គួរប្រើ `RESTRICT` ឫ `SET NULL`) ប៉ុន្តែការលុប Post មួយ គួរតែលុប Comments ទាំងអស់របស់វាយ៉ាងពិតប្រាកដ (គួរប្រើ `CASCADE`)។
