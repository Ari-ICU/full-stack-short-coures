## ⚡ អ្វីទៅជា Indexes?

ឧបមាថាអ្នកចង់ស្វែងរកពាក្យ "Database" នៅក្នុងសៀវភៅមួយក្បាលដែលមាន ៥០០ ទំព័រ។
- **គ្មាន Index (Sequential Scan):** អ្នកត្រូវបើកមើលទំព័រម្តងមួយៗតាំងពីទំព័រទី ១ ដល់ ៥០០។
- **មាន Index (Index Scan):** អ្នកបើកទៅទំព័រខាងក្រោយគេបង្អស់ដែលជារបៀបអក្សរអក្ខរក្រម រកអក្សរ "D" នោះវានឹងប្រាប់អ្នកថាពាក្យ "Database" ស្ថិតនៅទំព័រទី ៤២។ អ្នកបើកទៅទំព័រ ៤២ ភ្លាមៗតែម្តង!

នៅក្នុង Database **Index** គឺជាតារាងលាក់មុខមួយដែលរៀបចំទិន្នន័យតាមលំដាប់លំដោយ ដើម្បីជួយអោយការស្វែងរក (WHERE, JOIN, ORDER BY) មានល្បឿនលឿនដូចផ្លេកបន្ទោរ (ពីការស្វែងរក រាប់នាទី មកត្រឹមប៉ុន្មាន មីលីវិនាទី)។

## 🛠️ របៀបបង្កើត Indexes

### 1. Single Column Index
បង្កើត Index លើជួរឈរតែមួយ ដែលយើងឧស្សាហ៍យកមកប្រើក្នុងលក្ខខណ្ឌ `WHERE`។
```sql
-- បង្កើត Index សម្រាប់ស្វែងរកតាម Email អោយបានលឿន
CREATE INDEX idx_users_email
ON users(email);
```

### 2. Composite Index
បង្កើត Index លើជួរឈរច្រើនរួមគ្នា។ ស័ក្តិសមនៅពេលដែលអ្នកឧស្សាហ៍ស្វែងរកដោយប្រើលក្ខខណ្ឌ ទាំងពីរក្នុងពេលតែមួយ។
```sql
-- បង្កើត Index សម្រាប់ការស្វែងរកតាម ឈ្មោះ និង លេខទូរស័ព្ទ ក្នុងពេលតែមួយ
CREATE INDEX idx_users_name_phone
ON users(name, phone_number);
```

### 3. Unique Index
ធានាថាទិន្នន័យមិនអាចជាន់គ្នាបាន ព្រមទាំងបង្កើនល្បឿនស្វែងរក (នៅពេលអ្នកដាក់ `UNIQUE` constraint វានឹងបង្កើត Unique Index ដោយស្វ័យប្រវត្តិ)។
```sql
CREATE UNIQUE INDEX idx_users_username
ON users(username);
```

## ⚠️ ការថ្លឹងថ្លែង (Trade-offs)

តើយើងគួរដាក់ Index លើគ្រប់ Column ទាំងអស់តែម្តងទៅ ដើម្បីអោយលឿន? **អត់ទេ!**
> "Indexes ធ្វើអោយការអាន (Reads) លឿន ប៉ុន្តែវាធ្វើអោយការសរសេរ (Writes - INSERT/UPDATE/DELETE) យឺត និងស៊ីទំហំផ្ទុកច្រើន។"

**នៅពេលណាគួរប្រើ Index?**
- លើជួរឈរដែលឧស្សាហ៍ស្ថិតក្នុង `WHERE`
- លើ Foreign Keys
- លើជួរឈរដែលឧស្សាហ៍យកមករៀបលំដាប់ (ORDER BY)

## 🕵️‍♂️ ការវិភាគល្បឿនជាមួយ EXPLAIN

បើសិនជាកូដ SQL របស់អ្នកដើរយឺត តើអ្នកដឹងពីមូលហេតុដោយរបៀបណា? PostgreSQL មានមុខងារដ៏អស្ចារ្យមួយឈ្មោះថា `EXPLAIN`។

```sql
EXPLAIN
SELECT * FROM users WHERE email = 'test@example.com';
```
វានឹងបង្ហាញពី "ផែនការ" ថាវានឹងរត់ទៅរកទិន្នន័យដោយរបៀបណា (តើវាប្រើ Index (Index Scan) ឫវាដើររកគ្រប់ជួរ (Seq Scan))។

ចង់បានលទ្ធផលច្បាស់លាស់ជាមួយល្បឿនជាក់ស្តែង? ប្រើ `EXPLAIN ANALYZE`!
```sql
EXPLAIN ANALYZE
SELECT * FROM users WHERE email = 'test@example.com';
```
*(វានឹងដំណើរការកូដនេះមែនទែន ហើយប្រាប់អ្នកថាវាចំណាយពេលអស់ប៉ុន្មានមីលីវិនាទី `ms`)*
