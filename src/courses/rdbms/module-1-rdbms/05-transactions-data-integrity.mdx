## 🏛️ អ្វីទៅជា ACID Properties?

នៅក្នុងប្រព័ន្ធ RDBMS ទំនើប ស្ថិរភាព និងសុវត្ថិភាពទិន្នន័យគឺជាចំណុចស្នូល។ **ACID** គឺជាគោលការណ៍គ្រឹះទាំង ៤ ដែលធានាថាប្រតិបត្តិការ Database ទាំងអស់ត្រូវបានធ្វើឡើងដោយសុវត្ថិភាព៖

1.  **Atomicity (ភាពជាកញ្ចប់តែមួយ)**៖ រាល់ប្រតិបត្តិការទាំងអស់ក្នុង Transaction ត្រូវតែសម្រេចជោគជ័យទាំងអស់ ឬក៏ត្រូវត្រឡប់មកដូចដើមវិញទាំងអស់ (All or Nothing)។ គ្មានការសម្រេចពាក់កណ្តាលទីឡើយ។
2.  **Consistency (ភាពស៊ីសង្វាក់គ្នា)**៖ រាល់ការផ្លាស់ប្តូរទិន្នន័យទាំងអស់ត្រូវតែនាំ Database ពីស្ថានភាពសុពលភាពមួយ ទៅកាន់ស្ថានភាពសុពលភាពមួយទៀត ដោយមិនរំលោភលើច្បាប់ Constraints ឡើយ។
3.  **Isolation (ភាពឯកោ)**៖ ប្រតិបត្តិការចម្រុះ (Concurrent transactions) ដែលដើរទន្ទឹមគ្នា មិនត្រូវរំខាន ឬដឹងពីគ្នាឡើយ រហូតដល់វាត្រូវបានបញ្ចប់ជាផ្លូវការ។
4.  **Durability (ភាពជាប់លាប់)**៖ នៅពេលដែល Transaction ត្រូវបានរក្សាទុកជោគជ័យ (Committed) វានឹងរស់នៅជាអចិន្ត្រៃយ៍ ទោះបីជាមានការដាច់ភ្លើង ឬ Server គាំងភ្លាមៗក៏ដោយ។

## ⚙️ Transaction Control (BEGIN, COMMIT, ROLLBACK)

យើងគ្រប់គ្រងដំណើរការ Transaction តាមរយៈបញ្ជា ៣ យ៉ាង៖

*   **`BEGIN`** (ឬ `START TRANSACTION`): បើកកញ្ចប់ប្រតិបត្តិការថ្មីមួយ។
*   **`COMMIT`**: រក្សាទុកការប្រែប្រួលទាំងអស់ជាផ្លូវការ និងបញ្ចប់កញ្ចប់។
*   **`ROLLBACK`**: លុបចោលការប្រែប្រួលទាំងអស់ក្នុងកញ្ចប់នោះ ត្រឡប់ទិន្នន័យទៅកាន់ស្ថានភាពដើមវិញ (ករណីមានកំហុសកើតឡើង)។

## 🏦 សេណារីយ៉ូជាក់ស្តែង (Real-world Scenarios)

### សេណារីយ៉ូទី១៖ ការផ្ទេរប្រាក់ (Bank Transfer)
ឧបមាថា គណនី Sok ផ្ទេរប្រាក់ $100 ទៅអោយ Dara។ នេះទាមទារ DML ២ ជំហាន៖
1.  ដកប្រាក់ $100 ចេញពីគណនី Sok
2.  បូកប្រាក់ $100 ចូលគណនី Dara

ចុះបើជំហានទី១ ជោគជ័យ ស្រាប់តែ Server គាំង ឬដាច់បណ្តាញមុននឹងធ្វើជំហានទី២? ប្រាក់ Sok នឹងត្រូវបាត់បង់ដោយគ្មានមូលហេតុ! ដើម្បីការពារ យើងប្រើប្រាស់ Transaction៖

```sql
-- ចាប់ផ្តើម
BEGIN;

-- ជំហានទី១៖ ដកលុយពី Sok
UPDATE accounts 
SET balance = balance - 100.00 
WHERE owner = 'Sok';

-- ជំហានទី២៖ បន្ថែមលុយអោយ Dara
UPDATE accounts 
SET balance = balance + 100.00 
WHERE owner = 'Dara';

-- ប្រសិនបើគ្មានកំហុសអ្វីទេ រក្សាទុកផ្លូវការ
COMMIT;
```
*(ចំណាំ៖ ប្រសិនបើជំហានទី២ មានកំហុសឆ្គង ឬ balance របស់ Sok មិនគ្រប់គ្រាន់ ប្រព័ន្ធនឹងហៅ `ROLLBACK;` ភ្លាមៗ ធ្វើឱ្យលុយរបស់ Sok មិនត្រូវកាត់ឡើយ)*

### សេណារីយ៉ូទី២៖ ការលក់ទំនិញ (E-Commerce Checkout)
នៅពេលអតិថិជនកុម្ម៉ង់ទិញផលិតផល (Checkout)៖
1.  បង្កើតវិក្កយបត្រថ្មីនៅក្នុងតារាង `orders`
2.  ដកចំនួនស្តុកផលិតផលនៅក្នុងតារាង `products`

```sql
BEGIN;

-- ១. បង្កើត Order
INSERT INTO orders (id, user_id, total) 
VALUES ('order-uuid', 'user-uuid', 150.00);

-- ២. កាត់ស្តុកផលិតផល (ឧ. កាត់ស្តុកកៅអី ១)
UPDATE products 
SET stock = stock - 1 
WHERE id = 'product-uuid';

-- ត្រួតពិនិត្យ៖ បើស្តុកផលិតផលមិនគ្រប់គ្រាន់ (stock < 0) វានឹងរំលោភលើ CHECK constraint
-- ប្រព័ន្ធនឹងចាប់បាន Error ហើយធ្វើការ ROLLBACK!
COMMIT;
```
