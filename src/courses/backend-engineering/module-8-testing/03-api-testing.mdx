## 🔍 ការប្រៀបធៀបរបៀបធ្វើតេស្ត

ក្នុងនាមជាអ្នកអភិវឌ្ឍ (Developer) អ្នកត្រូវតែចេះធ្វើតេស្តទាំងពីរប្រភេទ៖

1. **Manual Testing (Postman / Thunder Client):**
   - **ពេលណាត្រូវប្រើ:** ពេលអ្នកកំពុងសរសេរកូដបណ្តើរ ចង់មើលលទ្ធផលបណ្តើរ ដើម្បីអោយប្រាកដថាកូដរត់បានតាមការគិត។
   - **ចំណុចខ្សោយ:** នៅពេល API អ្នកមានច្រើន (ឧទាហរណ៍ ៥០ Routes) អ្នកមិនអាចចំណាយពេលអង្គុយចុច Test ម្តងមួយៗរាល់ពេលកែប្រែកូដនោះទេ។

2. **Automated Testing (Jest + Supertest):**
   - **ពេលណាត្រូវប្រើ:** នៅពេលមុខងារនោះសរសេរចប់ ហើយចង់ធានាថាថ្ងៃក្រោយទោះមានការកែប្រែកូដ ក៏មិនធ្វើអោយមុខងារនោះ Error ដែរ។ កូដតេស្តនឹងរត់ដោយស្វ័យប្រវត្តិមុនពេលអ្នក Deploy ទៅកាន់ Production (CI/CD)។
   - **ចំណុចខ្សោយ:** ចំណាយពេលសរសេរកូដតេស្តយូរជាងពេលសរសេរកូដមុខងារទៅទៀត!

> [!TIP]
> នៅក្នុងការអនុវត្តជាក់ស្តែង ក្រុមហ៊ុនមិនសូវតម្រូវអោយអ្នកសរសេរតេស្ត ૧០០% នៃកម្មវិធី (100% Coverage) ទេ។ គេផ្តោតលើការសរសេរតេស្តសម្រាប់តែមុខងារសំខាន់ៗបំផុត (Core Business Logic) ប៉ុណ្ណោះ ដូចជាការទូទាត់លុយ និងប្រព័ន្ធ Login។
