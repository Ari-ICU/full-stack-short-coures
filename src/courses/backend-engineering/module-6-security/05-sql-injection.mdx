## 💉 អ្វីទៅជា SQL Injection?

**SQL Injection** គឺជាការវាយប្រហារដ៏ចំណាស់ ប៉ុន្តែនៅតែមានគ្រោះថ្នាក់បំផុតមួយ។ វាទាញយកចន្លោះប្រហោងពីការដែល Developer យកទិន្នន័យដែល Client បញ្ជូនមក ទៅតភ្ជាប់ (Concatenate) ជាកូដ SQL ផ្ទាល់ដោយមិនបានការពារ។

### ឧទាហរណ៍នៃកូដដែលមានគ្រោះថ្នាក់ ❌

```javascript
// ឧបមាថា user បញ្ជូន email មក: "admin@email.com' OR '1'='1"

const email = req.body.email;
// កូដខាងក្រោមនេះតភ្ជាប់ String ផ្ទាល់ (គ្រោះថ្នាក់ណាស់!!!)
const query = "SELECT * FROM users WHERE email = '" + email + "'";

// កូដ SQL ដែល Server នឹងអានគឺ:
// SELECT * FROM users WHERE email = 'admin@email.com' OR '1'='1'
// លទ្ធផល: លក្ខខណ្ឌ '1'='1' តែងតែពិត ដូច្នេះ Hacker អាចទាញយកទិន្នន័យ Users ទាំងអស់បាន!!
```

### វិធីការពារ (Parameterized Queries) ✅

រាល់ពេលអ្នកប្រើប្រាស់បណ្ណាល័យ (Library) Database ត្រូវតែប្រើ Parameterized Queries (`$1`, `$2`) ជានិច្ច ឫក៏ប្រើប្រាស់ ORM (Prisma/TypeORM)។

```tabs
javascript
// 1. បើប្រើ pg (Raw SQL)
const email = req.body.email;
// Database នឹងដឹងថា $1 គឺជា "ទិន្នន័យ" មិនមែនជា "កូដ SQL" ទេ ទោះ Hacker ដាក់អ្វីមកក៏ដោយ
const result = await pool.query(
    "SELECT * FROM users WHERE email = $1", 
    [email]
);
---
javascript
// 2. បើប្រើ TypeORM
const email = req.body.email;
// ORM នឹងធ្វើការការពារ SQL Injection ដោយស្វ័យប្រវត្តិ
const user = await userRepository.findOneBy({ email });
```
