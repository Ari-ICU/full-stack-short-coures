## 🏗️ ហេតុអ្វីបានជារចនាសម្ព័ន្ធសំខាន់?

នៅពេលគម្រោងកាន់តែធំ ឯកសារកាន់តែច្រើន។ បើយើងដាក់អ្វីៗគ្រប់យ៉ាងនៅក្នុង `app.js` នោះយើងនឹងមិនអាចគ្រប់គ្រងកូដបានឡើយ។ ការរៀបចំ Folder ជួយអោយការស្វែងរក និងកែប្រែកូដមានភាពងាយស្រួល (Maintainable)។

### រចនាសម្ព័ន្ធស្តង់ដារ (Feature-based vs Layer-based)

នៅក្នុងវគ្គនេះ យើងនឹងប្រើប្រាស់ទម្រង់ **Layer-based (Controller-Service-Repository)** ព្រោះវាពេញនិយមបំផុតសម្រាប់ Express និង NestJS។

```tabs
text
// រចនាសម្ព័ន្ធ Folder ដែលណែនាំ
src/
 ├── config/         # ផ្ទុកកូដតភ្ជាប់ទៅខាងក្រៅ (Database, AWS)
 ├── controllers/    # ទទួល Request, ឆ្លើយតប Response (គ្មាន Business Logic)
 ├── services/       # ផ្ទុក Business Logic សំខាន់ៗ (គណនា, ឆែកលក្ខខណ្ឌ)
 ├── repositories/   # ទាក់ទង Database (ប្រើ TypeORM)
 ├── entities/       # Database Models
 ├── middlewares/    # Custom Middlewares (Auth, Error Handler)
 ├── routes/         # បែងចែក Paths (ភ្ជាប់ទៅ Controller)
 ├── validators/     # Zod Schemas សម្រាប់ឆែកទិន្នន័យ
 ├── utils/          # កូដជំនួយខ្លីៗ (Helpers)
 └── app.js          # Entry Point (ផ្តុំកូដទាំងអស់នៅទីនេះ)
```

> [!TIP]
> សម្រាប់គម្រោងដែលធំមែនទែន គេនិយមប្រើទម្រង់ **Feature-based** វិញ ដោយផ្តុំកូដតាមផ្នែក ឧទាហរណ៍៖ `src/users/`, `src/products/` ជាដើម។
