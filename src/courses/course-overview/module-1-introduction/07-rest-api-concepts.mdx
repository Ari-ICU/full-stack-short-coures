## 🔗 អ្វីទៅជា API?

**API (Application Programming Interface)** គឺជាស្ពានចម្លងដែលអនុញ្ញាតឱ្យកម្មវិធីពីរផ្សេងគ្នាអាចទំនាក់ទំនងគ្នាបាន ទោះបីជាកម្មវិធីទាំងពីរនោះសរសេរដោយភាសា Programming ខុសគ្នាក៏ដោយ។ 

នៅក្នុង Web Development ភាគច្រើនវាសំដៅទៅលើ Web API ដែលអនុញ្ញាតអោយ Frontend (ឧទាហរណ៍៖ React) អាចទាញយកទិន្នន័យពី Backend (ឧទាហរណ៍៖ Node.js)។

> 🍽️ **ឧទាហរណ៍ប្រៀបធៀប (The Restaurant Analogy):** 
> ស្រមៃថាអ្នកកំពុងញ៉ាំអាហារនៅភោជនីយដ្ឋាន។ 
> - **អ្នក (Frontend)** ជាអ្នកមើលម៉ឺនុយ និងចង់កម្ម៉ង់ម្ហូប។
> - **ចុងភៅ (Database/Backend)** ជាអ្នកធ្វើម្ហូបនៅក្នុងផ្ទះបាយ។
> - តើអ្នកទៅប្រាប់ចុងភៅដោយផ្ទាល់ឬ? ទេ! អ្នកត្រូវការ **អ្នករត់តុ (API)**។ អ្នកប្រាប់អ្នករត់តុពីអ្វីដែលអ្នកចង់បាន អ្នករត់តុយកការកម្ម៉ង់ទៅប្រាប់ចុងភៅ ហើយពេលម្ហូបឆ្អិន អ្នករត់តុក៏យកម្ហូបនោះមកអោយអ្នកវិញ។

## 🏛️ អ្វីទៅជា REST?

មានរបៀបជាច្រើនក្នុងការសាងសង់ API ប៉ុន្តែរបៀបដែលពេញនិយមជាងគេបំផុតនាពេលបច្ចុប្បន្នគឺ **REST (Representational State Transfer)**។ 

REST មិនមែនជាភាសា Programming ថ្មីទេ ប៉ុន្តែវាគឺជា **ក្បួនខ្នាត (Architecture Style)** ដែលកំណត់ពីរបៀបដែល API គួរតែត្រូវបានរៀបចំឡើង ដើម្បីអោយមានស្តង់ដារ ងាយស្រួលយល់ និងងាយស្រួលអភិវឌ្ឍបន្ត។ API ដែលធ្វើតាមក្បួន REST ត្រូវបានគេហៅថា **RESTful API**។

### គោលការណ៍សំខាន់ៗរបស់ REST API

1. **Stateless (គ្មានការចងចាំស្ថានភាព):**
   រាល់សំណើ (Request) នីមួយៗដែល Client ផ្ញើទៅ Server ត្រូវតែមានព័ត៌មានគ្រប់គ្រាន់ដើម្បីឱ្យ Server យល់។ Server នឹងមិនចងចាំពីអតីតកាលរបស់អ្នកទេ! (ឧទាហរណ៍៖ រាល់ការទាញយកទិន្នន័យឯកជន អ្នកត្រូវតែផ្ញើ Token សម្គាល់ខ្លួនជានិច្ច)។
   
2. **Resource-Based (ផ្អែកលើធនធាន):**
   ទិន្នន័យត្រូវបានចាត់ទុកជា "Resources" (ធនធាន) ដែលមានអាសយដ្ឋាន URL (Endpoints) ជាក់លាក់របស់វា។
   
3. **ការប្រើប្រាស់ HTTP Methods យ៉ាងត្រឹមត្រូវ:**
   REST ពឹងផ្អែកយ៉ាងខ្លាំងទៅលើ HTTP Methods (GET, POST, PUT, DELETE) សម្រាប់ការធ្វើ CRUD។ អ្នកមិនគួរប្រើ `POST` ដើម្បីទាញយកទិន្នន័យនោះទេ!

## 📍 ការរចនា URL (Endpoints) តាមក្បួន REST

ក្បួនសំខាន់បំផុតគឺ **"ប្រើប្រាស់នាមពហុវចនៈ (Plural Nouns) មិនមែនកិរិយាសព្ទទេ"** ព្រោះសកម្មភាពត្រូវបានបញ្ជាក់ដោយ HTTP Methods រួចហើយ។

✅ **ការអនុវត្តត្រឹមត្រូវ (RESTful):**
- `GET /users` (ទាញយកអ្នកប្រើប្រាស់ទាំងអស់)
- `GET /users/123` (ទាញយកអ្នកប្រើប្រាស់លេខរៀង 123)
- `POST /users` (បង្កើតអ្នកប្រើប្រាស់ថ្មី)
- `PUT /users/123` (កែប្រែអ្នកប្រើប្រាស់លេខរៀង 123)
- `DELETE /users/123` (លុបអ្នកប្រើប្រាស់លេខរៀង 123)

❌ **ការអនុវត្តមិនត្រឹមត្រូវ:**
- `GET /getAllUsers` (ខុសព្រោះមានពាក្យសកម្មភាព `get`)
- `POST /createUser` (ខុសព្រោះមានពាក្យសកម្មភាព `create`)

## 📄 ទម្រង់ទិន្នន័យ JSON

REST APIs អាចឆ្លើយតបទិន្នន័យជាទម្រង់ XML ឬ HTML ក៏បាន ប៉ុន្តែទម្រង់ដែលពេញនិយម និងមានប្រសិទ្ធភាពបំផុតគឺ **JSON (JavaScript Object Notation)**។

**ហេតុអ្វីបានជា JSON ពេញនិយម?**
- វាមានសភាពស្រាល (Lightweight) និងមានល្បឿនលឿន។
- វាងាយស្រួលអានសម្រាប់មនុស្ស។
- វាអាចបំប្លែងទៅជា Object (Parsing) យ៉ាងងាយស្រួលដោយភាសា Programming ស្ទើរតែទាំងអស់។

**ឧទាហរណ៍នៃទិន្នន័យ JSON:**

```json
{
  "id": 123,
  "name": "Sok Dara",
  "email": "dara@example.com",
  "isActive": true,
  "skills": ["React", "Node.js", "PostgreSQL"],
  "address": {
    "city": "Phnom Penh",
    "country": "Cambodia"
  }
}
```

នៅពេលអ្នកប្រើប្រាស់ React (Frontend) ហៅទៅកាន់ Endpoint `GET /users/123` នោះ Server (Backend) នឹងបញ្ជូនអត្ថបទ JSON ខាងលើនេះមកវិញ ដែល Frontend អាចយកទៅបង្ហាញនៅលើអេក្រង់បានយ៉ាងងាយស្រួល!
