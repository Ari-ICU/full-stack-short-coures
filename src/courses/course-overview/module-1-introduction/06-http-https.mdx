## 🌐 ភាសានៃអ៊ីនធឺណិត៖ HTTP

ប្រសិនបើ Client និង Server ចង់ទំនាក់ទំនងគ្នា ពួកវាត្រូវការ **"ភាសារួម"** មួយដែលទាំងសងខាងអាចស្តាប់គ្នាបានយល់។ ភាសានោះគឺ **HTTP (HyperText Transfer Protocol)**។ 

អ្នកអាចប្រៀបធៀប HTTP ទៅនឹង **"ច្បាប់ក្នុងការសរសេរសំបុត្រ"**។ នៅពេលអ្នកសរសេរសំបុត្រទៅនរណាម្នាក់ អ្នកត្រូវសរសេរអាសយដ្ឋានអ្នកទទួល អោយបានច្បាស់ ដាក់តែម និងសរសេរខ្លឹមសារខាងក្នុង។ ដូចគ្នាដែរ HTTP កំណត់ពីទម្រង់ (Format) ដែលសំណើ (Request) និងការឆ្លើយតប (Response) ត្រូវរៀបចំឡើង។

---

## 🔒 ហេតុអ្វីត្រូវមាន HTTPS?

**HTTPS (HyperText Transfer Protocol Secure)** គឺជាកំណែទម្រង់ដែលត្រូវបាន **"ចាក់សោរសុវត្ថិភាព"** របស់ HTTP។ 

នៅក្នុង HTTP ធម្មតា ទិន្នន័យត្រូវបានបញ្ជូនជាអក្សរធម្មតា (Plain text)។ ប្រសិនបើអ្នកវាយបញ្ចូលលេខកូដសម្ងាត់ (Password) ជនខិលខូចដែលស្ថិតនៅលើបណ្តាញ Wi-Fi តែមួយ អាចទាញយកទិន្នន័យនោះមកអានបានយ៉ាងងាយ។ 

**HTTPS** ដោះស្រាយបញ្ហានេះដោយប្រើប្រាស់បច្ចេកវិទ្យា **Encryption (SSL/TLS)**៖
- វាយកទិន្នន័យធម្មតា ទៅបំប្លែងជាកូដសម្ងាត់ដែលគ្មានអ្នកណាអាចអានយល់ (ឧទាហរណ៍៖ `Password123` ទៅជា `XyZ98!kLq...`)។
- ទោះបីជាជនខិលខូចចាប់ទិន្នន័យបាន ក៏ពួកគេមិនអាចបកប្រែវាបានឡើយ លុះត្រាតែមាន "កូនសោរ" (Private Key) ដែលមានតែ Server ប៉ុណ្ណោះដែលកាន់។

> 💡 **ចំណាំ:** បច្ចុប្បន្ន គេហទំព័រស្ទើរតែ ១០០% ត្រូវតែប្រើប្រាស់ HTTPS បើមិនដូច្នោះទេ Browser ដូចជា Google Chrome នឹងលោតសញ្ញាព្រមានពណ៌ក្រហម (Not Secure) ភ្លាមៗ។

## 📦 រចនាសម្ព័ន្ធរបស់ HTTP

មិនថាជា Request (សំណើ) ឫ Response (ការឆ្លើយតប) ទេ វាតែងតែមានធាតុផ្សំសំខាន់ៗ ២ ផ្នែក៖

### 1. Headers (ផ្នែកក្បាល)
ប្រៀបដូចជាស្រោមសំបុត្រ។ វាមានផ្ទុកព័ត៌មាន (Metadata) អំពីសំណើ ឬការឆ្លើយតប ដូចជា៖
- ប្រភេទនៃ Browser ដែលកំពុងប្រើ (User-Agent)
- ប្រភេទនៃទិន្នន័យ (Content-Type: ឧទាហរណ៍ `application/json`)
- កូដសម្ងាត់បញ្ជាក់អត្តសញ្ញាណ (Authorization Token)

### 2. Body (ផ្នែកតួខ្លួន)
ប្រៀបដូចជាសំបុត្រដែលនៅខាងក្នុង។ វាផ្ទុកទិន្នន័យពិតប្រាកដដែលអ្នកចង់បញ្ជូន (ឧទាហរណ៍៖ ទិន្នន័យដែលអ្នកបំពេញក្នុង Form, ឬអត្ថបទ និងរូបភាពដែល Server ផ្ញើមកវិញ)។ 

*(ចំណាំ៖ ការផ្ញើ Request ប្រភេទ GET ជាទូទៅមិនមានតួខ្លួន (Body) ទេ។)*

## 🛠️ HTTP Methods សំខាន់ៗ

នៅពេល Client ផ្ញើសំណើ វាតែងតែភ្ជាប់មកជាមួយ Method (កិរិយាសព្ទ) មួយដើម្បីប្រាប់ Server ពីអ្វីដែលវាចង់ធ្វើ (CRUD Operations)៖

- **`GET` (Read):** ស្នើសុំទាញយកទិន្នន័យពី Server (ឧទាហរណ៍៖ ទាញយកបញ្ជីមេរៀន)។ វាគ្រាន់តែជាការអាន មិនមានការកែប្រែអ្វីទាំងអស់។
- **`POST` (Create):** ផ្ញើទិន្នន័យថ្មីទៅអោយ Server រក្សាទុក (ឧទាហរណ៍៖ ចុះឈ្មោះគណនីថ្មី, បង្ហោះរូបភាព)។
- **`PUT` / `PATCH` (Update):** ស្នើសុំកែប្រែទិន្នន័យដែលមានស្រាប់នៅលើ Server (ឧទាហរណ៍៖ ប្តូរឈ្មោះអ្នកប្រើប្រាស់)។
- **`DELETE` (Delete):** ស្នើសុំលុបទិន្នន័យណាមួយចេញពី Server។

## 🚦 HTTP Status Codes (លេខកូដស្ថានភាព)

នៅពេល Server ឆ្លើយតប វាតែងតែភ្ជាប់លេខកូដចំនួន ៣ ខ្ទង់ ដើម្បីប្រាប់ពីលទ្ធផលនៃការងារ។ លេខកូដទាំងនេះត្រូវបានបែងចែកជា ៥ ក្រុម៖

- **1xx (Informational):** កំពុងទទួលសំណើ (កម្រប្រើក្នុងកម្រិត Web Developer)។
- **2xx (Success):** ជោគជ័យ!
  - `200 OK`: សំណើត្រូវបានបំពេញដោយជោគជ័យ។
  - `201 Created`: ទិន្នន័យថ្មីត្រូវបានបង្កើតដោយជោគជ័យ (ជាទូទៅឆ្លើយតបពី POST)។
- **3xx (Redirection):** ទំព័រត្រូវប្តូរទីតាំងទៅកន្លែងផ្សេង (Redirect)។
  - `301 Moved Permanently`: ទំព័រនេះត្រូវបានប្តូរអាសយដ្ឋានជារៀងរហូត។
- **4xx (Client Error):** កំហុសរបស់អ្នកប្រើប្រាស់ (Client)!
  - `400 Bad Request`: ទិន្នន័យដែលផ្ញើមកមិនត្រឹមត្រូវ។
  - `401 Unauthorized`: មិនទាន់បាន Login ចូលប្រព័ន្ធទេ។
  - `403 Forbidden`: បាន Login ចូលហើយ តែមិនមានសិទ្ធិមើលឯកសារនេះទេ។
  - `404 Not Found`: រកមិនឃើញទំព័រ ឬទិន្នន័យដែលស្នើសុំ។
- **5xx (Server Error):** កំហុសរបស់ Server ខ្លួនឯង!
  - `500 Internal Server Error`: មានបញ្ហា Code ឬ Database ដួលនៅលើ Server។
  - `502 Bad Gateway`: មានបញ្ហានៅប្រព័ន្ធ Network ខាងក្នុង។

ការយល់ដឹងពី HTTP Methods និង Status Codes គឺជាគ្រឹះដ៏សំខាន់បំផុត មុននឹងឈានទៅដល់ការបង្កើតនិងប្រើប្រាស់ API (Application Programming Interface) នៅក្នុងមេរៀនបន្ទាប់!
