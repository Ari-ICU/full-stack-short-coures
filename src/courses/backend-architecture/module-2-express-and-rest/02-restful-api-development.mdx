## 🏛️ អ្វីទៅជា RESTful API?

យើងធ្លាប់បានរៀនអំពី API នៅក្នុងមេរៀនផ្តើមរួចមកហើយ។ **REST (Representational State Transfer)** មិនមែនជាកូដ ឬ Framework ទេ ប៉ុន្តែវាគឺជា **ក្បួនខ្នាត (Architecture Style)** ដែលណែនាំពីរបៀបរៀបចំ API របស់អ្នកអោយមានស្តង់ដារល្អ។ 

API ណាដែលគោរពតាមក្បួនខ្នាតរបស់ REST ត្រូវបានគេហៅថា **RESTful API**។ 

---

## 📍 ច្បាប់ក្នុងការដាក់ឈ្មោះ URL (Endpoints)

នេះគឺជាច្បាប់មាស ៣ យ៉ាងដែលអ្នកត្រូវចងចាំពេលរចនា RESTful API៖

### ១. ប្រើនាម (Nouns) មិនមែនកិរិយាសព្ទ (Verbs)
URL គួរតែតំណាងឱ្យ **អ្វីមួយ (Resource)** មិនមែនជា **សកម្មភាព (Action)** ទេ។ សកម្មភាពត្រូវបានកំណត់ដោយ HTTP Method (GET, POST, PUT, DELETE) បាត់ទៅហើយ។

❌ **ខុស:** `/getUsers`, `/createArticle`, `/deleteProduct/5`
✅ **ត្រូវ:** `/users`, `/articles`, `/products/5`

### ២. ប្រើពហុវចនៈ (Plurals) ជានិច្ច
ដើម្បីរក្សាភាពស្មើគ្នា យើងគួរតែប្រើពហុវចនៈ (មានអក្សរ s នៅចុង) ជានិច្ច ទោះបីជាយើងចង់ទាញយកទិន្នន័យតែមួយក៏ដោយ។

❌ **ខុស:** `/user/1`, `/article/5`
✅ **ត្រូវ:** `/users/1`, `/articles/5`

### ៣. រៀបចំឋានានុក្រម (Hierarchy) អោយបានច្បាស់លាស់
ប្រសិនបើធនធានមួយស្ថិតនៅក្រោមធនធានមួយទៀត (ឧទាហរណ៍៖ Comment ស្ថិតនៅក្នុង Article) អ្នកអាចរៀបចំវាបែបនេះ៖

✅ `/articles/12/comments` (មានន័យថា៖ ទាញយក comments ទាំងអស់របស់ article លេខ 12)

## 🚦 ការប្រើប្រាស់ HTTP Methods ជាមួយ REST

តារាងខាងក្រោមនេះបង្ហាញពីការផ្គូផ្គង Method និង URL ជាទូទៅ៖

| HTTP Method | URL Endpoint | អត្ថន័យ |
|-------------|--------------|----------|
| `GET`       | `/users`     | ទាញយកបញ្ជីអ្នកប្រើប្រាស់ទាំងអស់ |
| `GET`       | `/users/1`   | ទាញយកព័ត៌មានអ្នកប្រើប្រាស់លេខ 1 |
| `POST`      | `/users`     | បង្កើតអ្នកប្រើប្រាស់ថ្មី |
| `PUT` / `PATCH`| `/users/1`   | កែប្រែព័ត៌មានអ្នកប្រើប្រាស់លេខ 1 |
| `DELETE`    | `/users/1`   | លុបអ្នកប្រើប្រាស់លេខ 1 |

## 🔢 ការប្រើប្រាស់ HTTP Status Codes

នៅពេល Server ឆ្លើយតបទៅកាន់ Client វាត្រូវមាន **Status Code** ដើម្បីប្រាប់ពីស្ថានភាពនៃលទ្ធផលនោះ (ជោគជ័យ បរាជ័យ ឬមានបញ្ហាអ្វីមួយ)។ 

លេខកូដត្រូវបានបែងចែកជា ៥ ក្រុម៖
- **2xx (ជោគជ័យ):** 
  - `200 OK`: ជោគជ័យទូទៅ (ឧ. GET ដំណើរការល្អ)
  - `201 Created`: ជោគជ័យក្នុងការបង្កើតអ្វីមួយថ្មី (ជាញឹកញាប់ប្រើជាមួយ POST)
- **4xx (កំហុសពីអ្នកប្រើប្រាស់ / Client Error):**
  - `400 Bad Request`: ទិន្នន័យដែលផ្ញើមកខុសទម្រង់ ឬមិនគ្រប់គ្រាន់
  - `401 Unauthorized`: មិនទាន់ Login គ្មានសិទ្ធិមើល
  - `403 Forbidden`: បាន Login តែគ្មានសិទ្ធិ (ឧ. អត់មានសិទ្ធិជា Admin)
  - `404 Not Found`: រកមិនឃើញអ្វីដែលស្នើសុំ
- **5xx (កំហុសពី Server / Server Error):**
  - `500 Internal Server Error`: កូដក្នុង Server ដំណើរការខុសប្រក្រតី (គាំង)

### ឧទាហរណ៍ការប្រើក្នុង Express

```javascript
app.post('/users', (req, res) => {
    const { name, email } = req.body;
    
    // បើគ្មានទិន្នន័យ name ឬ email ទេ នោះបោះកំហុស 400 ទៅវិញ
    if(!name || !email) {
        return res.status(400).json({ error: "Name and email are required" });
    }
    
    // បើជោគជ័យ បោះលេខ 201
    res.status(201).json({ 
        message: "User created successfully", 
        user: { name, email } 
    });
});
```

នៅក្នុងមេរៀនបន្ទាប់ យើងនឹងរៀនពីរបៀបគ្រប់គ្រងកំហុស (Error Handling) ឱ្យបានត្រឹមត្រូវ និងមានសុវត្ថិភាពខ្ពស់ជាងនេះ។
