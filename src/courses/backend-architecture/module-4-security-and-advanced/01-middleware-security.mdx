## 🛡️ សុវត្ថិភាពជាចម្បង (Security First)

នៅពេលដែលអ្នកដាក់ API របស់អ្នកនៅលើអុីនធឺណិត (Deploy) អ្នកណាក៏អាចហៅវាបានដែរ រួមទាំង Hacker ផងដែរ។ ដូច្នេះ ការប្រើប្រាស់ Express ធម្មតាមិនទាន់មានសុវត្ថិភាពគ្រប់គ្រាន់ទេ យើងត្រូវបន្ថែម **Middleware** មួយចំនួនដើម្បីការពារខ្លួន។

---

## ១. ការពារ HTTP Headers (Helmet)

**Helmet** គឺជាកញ្ចប់មួយដែលជួយកំណត់ HTTP Headers ផ្សេងៗដើម្បីបិទបាំងព័ត៌មានលម្អិតរបស់ Server របស់យើង (ឧទាហរណ៍ ការបិទមិនអោយគេដឹងថាយើងកំពុងប្រើ Express) និងការពារការវាយប្រហារប្រភេទ XSS។

```bash
npm install helmet
```

```javascript
const express = require('express');
const helmet = require('helmet');

const app = express();

// ដាក់នៅខាងលើគេបង្អស់
app.use(helmet());
```

## ២. ការគ្រប់គ្រងការចូលប្រើ (CORS)

តាមលំនាំដើម Browser មិនអនុញ្ញាតអោយវេបសាយ `abc.com` ទៅហៅ API ពី `xyz.com` ទេ (ដើម្បីការពារកុំអោយគេលួចទិន្នន័យ)។ បើយើងចង់អោយ Frontend របស់យើងអាចហៅ API របស់យើងបាន យើងត្រូវបើក **CORS (Cross-Origin Resource Sharing)**។

```bash
npm install cors
```

```javascript
const cors = require('cors');

// អនុញ្ញាតអោយគ្រប់គ្នាអាចហៅបាន (មិនសូវមានសុវត្ថិភាព)
// app.use(cors()); 

// ជម្រើសល្អ៖ អនុញ្ញាតតែ Frontend របស់យើងប៉ុណ្ណោះ
const corsOptions = {
  origin: 'https://myfrontend.com',
  optionsSuccessStatus: 200
};

app.use(cors(corsOptions));
```

## ៣. ការពារការវាយប្រហារ DDOS (Rate Limiting)

Hacker អាចបញ្ជូន Requests ១ម៉ឺនដងក្នុងមួយវិនាទីដើម្បីធ្វើអោយ Server របស់អ្នកគាំង (Denial of Service - DoS)។ យើងត្រូវដាក់កម្រិតកំណត់ (Rate Limit) ថាតើ IP មួយអាចហៅ API បានប៉ុន្មានដងក្នុងមួយនាទី។

```bash
npm install express-rate-limit
```

```javascript
const rateLimit = require('express-rate-limit');

// កំណត់ថា IP នីមួយៗអាចហៅបានតែ ១០០ ដងប៉ុណ្ណោះក្នុងរយៈពេល ១៥ នាទី
const limiter = rateLimit({
  windowMs: 15 * 60 * 1000, // 15 នាទី
  max: 100, // អតិបរមា 100 requests
  message: "អ្នកបានស្នើសុំច្រើនដងពេកហើយ សូមរង់ចាំបន្តិច!"
});

// អនុវត្តលើ Routes ទាំងអស់
app.use(limiter);
```

ដោយគ្រាន់តែបន្ថែម Middleware ទាំង ៣ បន្ទាត់នេះ កម្មវិធី Backend របស់អ្នកមានសុវត្ថិភាពជាងមុនដល់ទៅ ៨០% ទៅហើយ!
