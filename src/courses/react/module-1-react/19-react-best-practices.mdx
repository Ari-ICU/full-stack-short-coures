## 🏆 ក្បួនខ្នាតល្អៗសម្រាប់អ្នកសរសេរ React (Best Practices)

សូមអបអរសាទរ! ពេលនេះអ្នកបានរៀនចប់នូវមុខងារសំខាន់ៗរបស់ React អស់ហើយ។ មុននឹងឈានចូលទៅកាន់ Next.js យើងសូមចែករំលែកនូវបទពិសោធន៍ និងក្បួនល្អៗដែលអ្នកអភិវឌ្ឍន៍ជំនាញៗ (Senior Developers) តែងតែអនុវត្ត។

---

## 1. បំបែក Components អោយតូចៗ (Keep Components Small)

កុំព្យាយាមសរសេរកូដ HTML ទាំងមូលរបស់ទំព័រចូលទៅក្នុង Component តែមួយអោយសោះ។
គោលការណ៍ **Single Responsibility Principle (SRP)** បានចែងថា "Component មួយគួរតែធ្វើការងារតែមួយមុខគត់"។

```jsx
// ❌ មិនល្អ: Component ធំពេក ពិបាកមើលថែទាំ
export default function Dashboard() {
  return (
    <div>
      <nav>Sidebar Navigation កូដវែងអន្លាយ...</nav>
      <header>Top Bar កូដវែងអន្លាយ...</header>
      <main>បញ្ជីទិន្នន័យ (Table) កូដវែងអន្លាយ...</main>
    </div>
  );
}

// ✅ ល្អ: បំបែកជា Component តូចៗ
export default function Dashboard() {
  return (
    <div className="dashboard-layout">
      <Sidebar />
      <div className="content">
        <TopBar />
        <DataTable />
      </div>
    </div>
  );
}
```

## 2. រៀបចំ Folder តាមលក្ខណៈពិសេស (Feature-based folders)

ពេលគម្រោងកាន់តែធំ កុំដាក់ Components ទាំងអស់ចូកឡូកគ្នាក្នុង Folder តែមួយ។ គួររៀបចំវាទៅតាមមុខងារ (Features) ឬទំព័រ (Pages) វិញ។

**ទម្រង់រៀបចំដែលពេញនិយម:**
```text
src/
 ├─ components/     # សម្រាប់ Component ដែលប្រើរួមគ្នា (ប៊ូតុង, Modal)
 ├─ features/       # បែងចែកតាមមុខងារ (ឧ. Authentication, UserProfile)
 ├─ hooks/          # សម្រាប់ Custom Hooks ទាំងអស់
 ├─ pages/          # សម្រាប់ Component ធំៗដែលតំណាងអោយទំព័រនីមួយៗ
 ├─ services/       # សម្រាប់កូដហៅ API (fetch/axios)
 └─ App.jsx
```

## 3. ចៀសវាងការ Prop Drilling ជ្រៅពេក

ដូចដែលបានរៀនក្នុងមេរៀន Context API បើអ្នកត្រូវបញ្ជូន Props កាត់ Component ច្រើនជាង ៣ តំណ គួរពិចារណាប្រើប្រាស់៖
- **Context API**
- **Zustand** ឬ **Redux** (សម្រាប់គម្រោងធំៗ)
- ការប្រើប្រាស់ **Component Composition** (ការបញ្ជូន Component ជា `children` ជំនួសអោយការបញ្ជូនទិន្នន័យធម្មតា)។

## 4. ដឹងថាពេលណាត្រូវប្រើ State

កុំយកទិន្នន័យគ្រប់យ៉ាងទៅញាត់ក្នុង `useState` ទាំងអស់អោយសោះ! បើទិន្នន័យមួយអាចគណនាបានពីទិន្នន័យមួយទៀត អ្នកមិនចាំបាច់បង្កើត State ថ្មីទេ។

```jsx
// ❌ មិនល្អ: បង្កើត State ជាន់គ្នា (Redundant State)
const [firstName, setFirstName] = useState("សុខ");
const [lastName, setLastName] = useState("សាន្ត");
const [fullName, setFullName] = useState("សុខ សាន្ត"); // មិនចាំបាច់មានទេ!

// ✅ ល្អ: គណនាវាដោយផ្ទាល់
const [firstName, setFirstName] = useState("សុខ");
const [lastName, setLastName] = useState("សាន្ត");
const fullName = `${firstName} ${lastName}`; 
```

## 5. ការដាក់ឈ្មោះ (Naming Conventions)

- **Components:** ត្រូវចាប់ផ្តើមដោយអក្សរធំជានិច្ច (PascalCase) ឧ. `UserProfile`, `SubmitButton`។
- **ឯកសារ (Files):** គួរដាក់ឈ្មោះឯកសារអោយដូចឈ្មោះ Component (ឧ. `UserProfile.jsx`)។
- **Custom Hooks:** ត្រូវផ្តើមដោយ `use` ជានិច្ច (camelCase) ឧ. `useAuth`, `useFetchData`។
- **Event Handlers:** ប្រើប្រាស់ពាក្យ `handle` សម្រាប់ឈ្មោះ Function (ឧ. `handleClick`, `handleSubmit`) និងពាក្យ `on` សម្រាប់ឈ្មោះ Prop (ឧ. `<Button onClick={handleClick} />`)។
