## 🚦 ១. Mechanics of `useState` & Re-render Cycle

> [!IMPORTANT]
> **និយមន័យ React State & useState (Definition) ៖**  
> យោងតាមគេហទំព័រផ្លូវការរបស់ React (**react.dev**), **React State** គឺជាអង្គចងចាំផ្ទាល់ខ្លួន (Component Memory) សម្រាប់រក្សាទុកទិន្នន័យដែលអាចផ្លាស់ប្តូរបានទៅតាមពេលវេលា ឬសកម្មភាពរបស់អ្នកប្រើប្រាស់ (User Interactions)។  
> 
> Hook **`useState`** ផ្តល់ត្រឡប់មកវិញនូវ Array មាន ២ ធាតុ ៖ `[stateValue, setterFunction]` ៖
> 1. **`stateValue` ៖** តម្លៃបច្ចុប្បន្ននៃ State ក្នុង Render មួយនេះ (Snapshot)។
> 2. **`setterFunction` ៖** Function សម្រាប់ប្រាប់ React ឱ្យធ្វើបច្ចុប្បន្នភាព State និង **កេះដំណើរការ Re-render (Trigger a Render)**។

## 📸 ២. The "State as a Snapshot" Mental Model (react.dev Standard)

រឿងដែល Developer ថ្មីៗតែងតែយល់ច្រឡំ ៖
```javascript
console.log(count); // 0
setCount(count + 1);
console.log(count); // នៅតែ 0 ដដែល! មិនទាន់ក្លាយជា 1 ភ្លាមៗទេ!
```

> [!NOTE]
> **ហេតុអ្វី?**  
> យោងតាម `react.dev`, **State មិនមែនជា Regular JavaScript Variable ធម្មតាឡើយ**! វាមិនផ្លាស់ប្តូរភ្លាមៗក្នុងបន្ទាត់បន្ទាប់ទេ ប៉ុន្តែវាដើរតួដូចជា **រូបថត (Snapshot)** មួយសន្លឹកនៃ Render បច្ចុប្បន្ន។  
> ការហៅ `setCount(...)` មិនមែនជាការប្តូរអថេរក្នុងបន្ទាត់នោះទេ តែវាជាការ **ផ្ញើសារកក់កាលវិភាគទៅ React** ថា ៖ *«សូមថតរូប Component នេះម្តងទៀតក្នុង Render បន្ទាប់ ដោយជំនួសតម្លៃ count = 1!»*

## 💻 ៣. ឧទាហរណ៍ជាក់ស្តែង ៖ Functional Updates & Automatic Batching

```jsx
// src/components/CounterMastery.jsx
import { useState } from 'react';

export default function CounterMastery() {
  const [count, setCount] = useState(0);

  // 1. របៀបធម្មតា (Direct Value Update)
  const handleAddOne = () => {
    setCount(count + 1);
  };

  // 2. របៀប Functional Updates (Safe Queued Updates)
  const handleAddThree = () => {
    // React នឹងយក callback functions ទាំង ៣ នេះទៅដាក់ក្នុង Queue ដើម្បីគណនាបន្តកន្ទុយគ្នា
    setCount((prev) => prev + 1); // prev = 0 -> return 1
    setCount((prev) => prev + 1); // prev = 1 -> return 2
    setCount((prev) => prev + 1); // prev = 2 -> return 3
  };

  const handleReset = () => {
    setCount(0);
  };

  return (
    <div className="max-w-xs mx-auto p-6 bg-white dark:bg-slate-900 border border-slate-200 dark:border-slate-800 rounded-2xl shadow-lg text-center space-y-4">
      <span className="text-xs font-bold uppercase tracking-wider text-slate-400">
        Current Count
      </span>
      <h2 className="text-5xl font-black text-slate-800 dark:text-white">
        {count}
      </h2>

      <div className="flex gap-2 justify-center">
        <button
          onClick={handleAddOne}
          className="px-3 py-2 bg-slate-100 hover:bg-slate-200 text-slate-700 text-xs font-bold rounded-xl transition"
        >
          +1 ធម្មតា
        </button>

        <button
          onClick={handleAddThree}
          className="px-3 py-2 bg-blue-600 hover:bg-blue-700 text-white text-xs font-bold rounded-xl transition shadow-sm"
        >
          +3 Functional
        </button>

        <button
          onClick={handleReset}
          className="px-3 py-2 bg-rose-50 hover:bg-rose-100 text-rose-600 text-xs font-bold rounded-xl transition"
        >
          Reset
        </button>
      </div>
    </div>
  );
}
```

## ⚡ ៥. Automatic Batching ក្នុង React 18 & 19

តើមានអ្វីកើតឡើងប្រសិនបើអ្នកហៅ State Setters ច្រើនក្នុង Handler តែមួយ?
```javascript
function handleClick() {
  setCount(c => c + 1);
  setFlag(f => !f);
  setUser('Dara');
}
```
* **ក្នុងជំនាន់ចាស់ (React 17 ចុះក្រោម) ៖** បើកូដនេះស្ថិតក្នុង `fetch()` ឬ `setTimeout` វានឹងធ្វើឱ្យ React ត្រូវ Re-render ចំនួន ៣ ដងដាច់ដោយឡែកពីគ្នា!
* **ក្នុងជំនាន់ថ្មី (React 18 & 19) ៖** React មានមុខងារ **Automatic Batching** — វានឹងប្រមូលផ្តុំរាល់ State Updates ទាំងអស់បញ្ចូលគ្នាតែមួយ ហើយ Re-render តែ **១ ដងគត់** នៅចុងបញ្ចប់ ដែលជួយបង្កើនល្បឿន និង Performance យ៉ាងអស្ចារ្យ!

## 📋 ៦. សង្ខេបចំណុចសំខាន់ៗ (Key Takeaways)

- **State** គឺជា Component Memory — ការហៅ Setter Function (`setCount`) គឺជាវិធីតែមួយគត់ដើម្បីកេះ Re-render។
- **State as a Snapshot ៖** តម្លៃ State នៅដដែលពេញមួយ Render cycle នោះ វាមិនប្តូរភ្លាមៗក្នុងបន្ទាត់បន្ទាប់ឡើយ។
- ប្រើ **Functional Updates (`prev => prev + 1`)** ជានិច្ច នៅពេល State ថ្មីពឹងផ្អែកលើតម្លៃចាស់។
- React 18/19 ប្រើ **Automatic Batching** ដើម្បីបង្រួម Multi-state updates ឱ្យ Re-render តែមួយដងគត់។
