## ⏳ ការរង់ចាំដ៏គួរអោយធុញ (Loading State)

នៅក្នុងគេហទំព័រដែលទាញយកទិន្នន័យច្រើនពី Database (Server Components) វាអាចប្រើពេល ១ ទៅ ៣ វិនាទីទើបទំព័រអាចបង្ហាញចេញមកបាន។ ប្រសិនបើគ្មានអ្វីប្រាប់អ្នកប្រើប្រាស់ថាកម្មវិធីកំពុងដំណើរការទេ ពួកគេអាចគិតថាគេហទំព័រគាំង ហើយបិទវាចោល។

នៅក្នុង React ធម្មតា យើងត្រូវបង្កើត State `loading` រួចប្រើប្រាស់ `if (loading) return <Spinner />` យ៉ាងស្មុគស្មាញ។ 
នៅក្នុង Next.js អ្នកគ្រាន់តែបង្កើតឯកសារ **`loading.tsx`** មួយជាការស្រេច!

## 1. របៀបប្រើប្រាស់ `loading.tsx`

ឯកសារ `loading.tsx` ត្រូវបង្កើតនៅក្បែរ `page.tsx` នៃថតដែលអ្នកចង់បង្ហាញ Loading។

**រចនាសម្ព័ន្ធថត:**
```text
app/
 ├─ dashboard/
 │   ├─ page.tsx      (ទំព័រដែលទាញយកទិន្នន័យយូរ)
 │   └─ loading.tsx   (ទំព័រដែលនឹងបង្ហាញភ្លាមៗជំនួស page.tsx)
```

**ឯកសារ `app/dashboard/loading.tsx`:**
```tsx
export default function Loading() {
  // អ្នកអាចបង្កើត UI អោយស្អាតៗនៅទីនេះ (ឧ. រង្វង់វិលៗ, ឬ Skeleton)
  return (
    <div style={{ display: 'flex', justifyContent: 'center', padding: 50 }}>
      <h2>កំពុងរៀបចំទិន្នន័យ សូមរង់ចាំបន្តិច... 🔄</h2>
    </div>
  );
}
```

**ឯកសារ `app/dashboard/page.tsx`:**
```tsx
export default async function DashboardPage() {
  // ឧបមាថាការទាញយកទិន្នន័យនេះស៊ីពេល ២ វិនាទី
  await new Promise(resolve => setTimeout(resolve, 2000));

  return (
    <div>
      <h1>នេះគឺជាទំព័រផ្ទាំងគ្រប់គ្រង!</h1>
      <p>ទិន្នន័យត្រូវបានទាញយកដោយជោគជ័យ។</p>
    </div>
  );
}
```

## 2. តើវាដំណើរការយ៉ាងដូចម្តេចនៅពីក្រោយ? (React Suspense)

នៅពេលអ្នកប្រើប្រាស់ចុចតំណចូលទៅកាន់ `/dashboard` Next.js ដឹងថាទំព័រនេះត្រូវទាញយកទិន្នន័យយូរ។ ដូច្នេះវាធ្វើការរុំទំព័រ `page.tsx` នោះដោយស្វ័យប្រវត្តិជាមួយ `<Suspense>` របស់ React។

នៅពីក្រោយវាមានទម្រង់បែបនេះ៖
```tsx
<Layout>
  {/* បង្ហាញ Loading ខណៈពេលកំពុងរង់ចាំ Page */}
  <Suspense fallback={<Loading />}>
    <Page />
  </Suspense>
</Layout>
```

ដោយសារតែវារុំត្រឹម `Page` នោះមានន័យថា `Layout` (ដូចជា Navbar ឫ Sidebar) នឹងនៅតែបង្ហាញជាធម្មតា អ្វីដែលអណ្តែត Loading គឺមានតែផ្នែកខាងក្នុង (Content area) ប៉ុណ្ណោះ ដែលធ្វើអោយ UX គឺល្អឥតខ្ចោះ!
